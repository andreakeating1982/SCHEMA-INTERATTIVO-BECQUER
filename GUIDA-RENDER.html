GitHub

1
Crea un repository su GitHub
Dove "vive" il tuo progetto online

Un repository è come una cartella dove metti i file del progetto su internet.

  • Entra su github.com e clicca sul pulsante + in alto a destra
  • Scegli "New repository"
  • Come nome scrivi: schema-interattivo
  • Lascia selezionato "Public" (è gratis)
  • Clicca il grande pulsante verde "Create repository"
💡 Importante: Non spuntare "Add a README" o ".gitignore" — il progetto ha già i suoi file!
2
Carica i file del progetto
Trascina la cartella dello schema su GitHub

Ora che hai creato il repository vuoto, devi caricare i file dello schema:

  • Nella pagina del repository, clicca su "uploading an existing file"
  • Scarica il pacchetto ZIP del progetto (è incluso con questa guida)
  • Estrai lo ZIP sul tuo computer
  • Trascina TUTTI i file estratti nella pagina di GitHub (con il mouse, come quando copi file tra cartelle)
  • Scrivi un messaggio tipo: "Primo caricamento"
  • Clicca "Commit changes"
⚠️ Attenzione: Trascina TUTTI i file, non solo la cartella! Se vedi la scritta "We found 200+ files to commit", sei a posto.
3
Vai su Render e scegli "Blueprint"
Il modo più semplice per deployare

Ora entri in Render, la piattaforma che farà girare il tuo schema online:

  • Vai su dashboard.render.com
  • Clicca sul pulsante New + in alto a destra
  • Dal menu che si apre, scegli "Blueprint" (non "Web Service"!)
💡 Perché Blueprint? Perché il file render.yaml che ho preparato dice a Render cosa creare: l'app + il database, tutto automatico. Con "Web Service" dovresti configurare tutto a mano.
4
Collega il repository GitHub
Collega Render al progetto

Render ti chiederà di collegare il tuo GitHub:

  • Clicca su "Connect repository"
  • Se è la prima volta, autorizza Render a vedere i tuoi repository
  • Cerca il repository schema-interattivo nella lista
  • Clicca sul suo nome per selezionarlo
  • Render mostrerà un riepilogo di quello che sta per creare:
    ✅ Database: schema-db (PostgreSQL, gratuito)
    ✅ Web Service: schema-interattivo (Docker, gratuito)
5
Clicca "Apply" e attendi
Render fa tutto da solo — 3-5 minuti

Ora la parte più bella: Render fa tutto in automatico!

  • Clicca il grande pulsante Apply
  • Render inizierà a creare:
    1️⃣ Il database PostgreSQL (30 secondi)
    2️⃣ Il web Service con la tua app (3-5 minuti)
  • Vedrai una schermata con i log in tempo reale — sembra codice, ma non preoccuparti, è normale
  • Quando vedi "Service is live 🎉" in verde, è pronto!
⏳ Pazienza: La prima volta ci mette 3-5 minuti perché deve "impacchettare" l'app. È normale. Fai un ☕ caffè mentre aspetti!
6
La tua app è live! 🎉
Apri lo schema e provalo

Quando il deploy è completo, vedrai il pulsante per aprire l'app:

  • Clicca sul link che Render ti mostra:
    https://schema-interattivo.onrender.com
  • Si aprirà una nuova scheda con il tuo schema funzionante!
  • Provalo subito: crea una classe, apri un'altra scheda come studente, entra col codice

🎉 App live!

Il tuo Schema Interattivo è online e funzionante a questo indirizzo:

https://schema-interattivo.onrender.com

7
Aggiungi il link sul blog Blogger
I tuoi studenti troveranno lo schema dal blog

Ora colleghiamo lo schema al tuo blog. È il passo più semplice:

  • Vai su Blogger → "Layout"
  • Clicca su "Aggiungi un Gadget" nella barra laterale o nel menu
  • Scegli "Link List"
  • Inserisci:
    Titolo: Schema Interattivo
    URL: https://schema-interattivo.onrender.com
  • Clicca "Salva" e poi "Salva disposizione"
  • Vai a vedere il tuo blog — ora c'è il link allo schema! 🎉
💡 Consiglio: Quando clicchi sul link durante la lezione, lo schema si apre in una nuova scheda. Proiettalo alla LIM e gli studenti entrano col codice dal telefono!

Hai problemi? Cose da sapere
Soluzioni ai problemi più comuni
"Mi dice che il repository non è stato trovato"
Vai su GitHub, apri il repository e controlla che ci siano i file. Se è vuoto, ripeti il Passo 2.
"Il deploy fallisce"
Clicca sui log e cercami la riga rossa. Di solito è un problema di connessione — riprova cliccando "Manual Deploy" → "Deploy latest commit".
"Il caricamento su GitHub è lento"
È normale se hai molti file. GitHub mostra "Crunching" — aspetta che finisca prima di cliccare "Commit changes".
